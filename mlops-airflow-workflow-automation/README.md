# MLOps — Workflow Automation Using Apache Airflow

## Objective

Build and automate an e-commerce data processing workflow using **Apache Airflow**.

The project demonstrates how Airflow can orchestrate multiple data-engineering tasks with dependencies, scheduling, monitoring, logging, and validation.

---

## Workflow

The Airflow DAG consists of five sequential tasks:

```text
check_raw_data
       ↓
     clean
       ↓
feature_engineering
       ↓
   validate
       ↓
    report
```

The DAG ID is:

```text
ecommerce_orders_etl_pipeline
```

# Dataset

The project uses an intentionally imperfect synthetic e-commerce orders dataset.

### Dataset size

- **Rows:** 1,805
- **Columns:** 19
- **Duplicate records:** 5

The dataset intentionally contains data-quality issues to demonstrate a realistic ETL workflow.

### Included issues

- Missing values
- Invalid numeric values
- Invalid dates
- Whitespace inconsistencies
- Duplicate records
- Outliers
- Invalid domain values

Examples include:

```text
quantity = unknown
unit_price = N/A
order_date = not_available
customer_age = 125
quantity = 100
delivery_days = 60
```

# 3. Configure Airflow


Verify the DAG folder:


# Running the Workflow

Inside the Airflow UI:

1. Open the **DAGs** page.
2. Search for:

```text
ecommerce_orders_etl_pipeline
```

3. Enable/unpause the DAG if necessary.
4. Open the DAG.
5. Click **Trigger**.
6. Monitor the task execution.

The tasks execute in the following order:

```text
check_raw_data
        ↓
clean
        ↓
feature_engineering
        ↓
validate
        ↓
report
```

---

# Task Description

## 1. check_raw_data

Checks whether the raw dataset exists and contains data.

It reports:

- Number of rows
- Number of columns
- Duplicate rows
- Missing cells

---

## 2. clean

Cleans the raw e-commerce dataset.

The cleaning process includes:

- Removing exact duplicates
- Removing unnecessary whitespace
- Converting numeric columns
- Handling invalid numeric values
- Validating numeric ranges
- Parsing dates

Output:

```text
data/processed/orders_cleaned.csv
```

---

## 3. feature_engineering

Creates additional features from the cleaned dataset.

Examples include:

```text
gross_amount
discount_amount
calculated_net_amount
order_year
order_month
order_quarter
order_day_of_week
is_weekend
age_group
delivery_delay_days
delivery_delay_flag
high_discount_flag
quantity_per_1000_value
days_since_order
```

Output:

```text
data/processed/orders_features.csv
```

---

## 4. validate

Validates the feature-engineered dataset.

The validation checks:

- Required feature columns
- Dataset availability
- Required feature completeness

Output:

```text
reports/validation_report.json
```

A successful workflow produces:

```json
{
  "status": "PASS"
}
```

---

## 5. report

Generates a summary of the processed dataset.

Output:

```text
reports/pipeline_summary.json
```

The report contains information such as:

- Number of rows
- Number of columns
- Numeric feature count
- Categorical feature count
- Feature column names

# Learning Outcome

The main objective of this assignment is to understand how Apache Airflow can automate and orchestrate a multi-step data pipeline.

Instead of manually running:

```text
check → clean → feature engineer → validate → report
```

Airflow manages the complete workflow through a DAG.

This provides:

- Automated execution
- Dependency management
- Scheduling
- Monitoring
- Failure visibility
- Task-level logs
- Reproducible workflows
